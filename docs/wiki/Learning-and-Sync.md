# 学习与同步

> **适用场景：** 你想更新已生成的 Skills，理解学习阶段，或决定何时只学习、只生成、续跑或重来。

## 选择正确命令

| 目标 | 命令 | 是否生成 Skills |
|---|---|---|
| 日常更新项目知识与产物 | `skills-seed sync` | 是，学习成功且需要刷新时生成 |
| 只学习，不改动生成目录 | `skills-seed learn current` | 否 |
| 已有学习数据，只重新渲染产物 | `skills-seed generate skills` | 是 |
| 预览哪些文件会参与学习 | `skills-seed preview files --mode incremental` | 否 |

完整参数见 [命令参考](../COMMANDS.md)。

## 当前代码学习链路

`learn current` / `sync` 的关键阶段如下：

```text
准备项目上下文
  -> 本地过滤与增量候选
  -> 学习议程规划
     AI 只返回高价值源码焦点；未分配路径由 `learning.current.agenda.fallback_paths_per_focus` 拆成少量可恢复的覆盖安全网，不代表这些路径已被判定为低价值
  -> 隔离源码证据分析
  -> 独立知识审查
  -> 知识准入与入库
  -> 权威规则与项目地图刷新
  -> 生成 Skills
```

本地代码负责路径范围、输入覆盖、结构化契约、来源安全和持久化。Agent 负责基于已给证据判断语义、边界和可复用价值。两者各自承担擅长的部分，避免把业务判断硬编码到本地过滤器中。

## 焦点、并发与审查

- 每个焦点围绕一个有证据的责任或行为边界分析。
- 焦点是一次可恢复的分析批次，不是最终 Skill 的分类目录；相邻责任共享同一改动边界时应合并，通常保持少量开发焦点，只有独立高风险边界才单独拆分。
- 源码分析可按配置并行处理独立焦点；并发数由 `agent.parallelism` 控制。
- Claude 与 Codex 的实际运行时 Schema 会按当前批次收紧焦点 ID 枚举与结果数量；增量候选未通过本地证据准入时，若该焦点没有其他合格决策，则保留唯一的 `no_change` 回执，不会把“无可入库模式”误判为“遗漏焦点”。
- 独立知识审查按完整焦点进行，避免按候选数量机械切分而丢失上下文。
- 议程规划完成后立即保存焦点列表；每个焦点完成源码分析和审查后再次保存 checkpoint。中断后会复用已保存议程，只重试尚未完成的焦点。`--resume` 是复用有效状态的请求，不是强制跳过规划；任一已记录源码的内容哈希变化、当前变更超出旧状态范围或显式重启都会使旧状态失效并重新规划，单独升级 CLI 不会因版本号变化触发重规划。
- 续跑会重新校验已保存的 Pattern 规范化决策。本轮源码候选先以自己的 Pattern ID 重建来源身份，历史 `MergedFrom` 只保留为既有输出谱系，不会回流为当前输入归属；同 ID 当前候选作为该 Pattern 的当前版本覆盖已有记录。重复校验已水合结果时，无歧义谱系只回指其当前有效 Pattern，同一谱系有多个所有者时仍会拒绝。若某条决策确实合并了不同 ID 的能力入口，系统会保留独立候选并覆盖该 checkpoint，不会让错误合并进入模式库或中断入库。
- Pattern 入库、源码基线和项目地图刷新是分阶段提交的。若中断发生在 Pattern 已入库之后，续跑会恢复已提交的候选发现数、规范化写入数和原始变更范围，`sync` 仍会按上次学习结果判断是否需要生成 Skills。
- 学习摘要区分“发现候选模式”和“规范化写入”：前者是本轮审查后的候选数，后者是包含相关既有 Pattern 在内的最终 upsert 数，因此规范化写入数可能更大。
- workspace `sync` 会在每个子项目的最终进度中区分“有学习变化”“无学习变化并跳过生成”和“无学习变化但补全缺失 Skills”，并在子项目全部完成后汇总变化项目数、文件变化、候选模式、规范化写入和移除数量。工作区关系输入未变化只表示跨项目画像与规范无需重算，不表示子项目没有学习产出。

并发提高吞吐，但会增加 Agent 调用压力。应按服务限额和项目规模设置，而不是盲目提高数值。

## 成功与失败边界

学习成功不代表 Agent 自动证明所有代码都正确。它表示本轮可接受的知识已满足来源、范围、证据和结构校验。生成阶段只消费已保存结果，不重新调用 Agent。

遇到 Agent 调用失败、Schema 不兼容或输入覆盖校验失败时，系统不会把半完成结论直接写入模式库。先查看 [学习失败与人工修正](Learning-Failures-and-Manual-Repair.md) 中的 runtime 归档和续跑策略。

## 何时强制重新生成

以下情况通常应执行 `skills-seed generate skills`：

- 新增、更新或删除 Rule / Workflow 后。
- 手动维护 pattern 或 profile 后。
- 切换 Skills 目标或输出路径后。
- 需要验证生成模板变化后的交付内容时。

生成会重建 Skills Seed 管理的输出目录。对产物的手工修改应迁移回 `.skills-seed` 中相应的事实源。
